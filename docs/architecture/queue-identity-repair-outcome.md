# Reviewed failed-task identity repair outcome

## Implementation — 13 October 2026

Implemented the [reviewed-repair design](queue-identity-repair-design.md) in small
ES modules: contract, repository, coordinator, separate retry and HTTP routes.
Command Center offers explicit review, work/edition confirmation, a saved receipt
lookup and a separate routing-capable retry. Named client API functions preserve
the existing GET/mutation conventions and disable automatic transport retries.

Only supported flat, unenriched movie/series requests qualify. Nested/alternate
identities, inventory/reprocess context, missing or contradictory evidence,
exhausted attempts and possible prior effects remain unresolved. Legacy/nested
competing requests are checked even though they cannot themselves be repaired by
this first implementation. This is not a general webhook canonicalization change.

The original webhook, task title, history, attempt budget and metadata-recovery
ledger are preserved. Confirmation changes only the task ID and a receipt marker,
leaving status failed. Ordinary Retry, Retry All and same-ID background recovery
exclude repaired tasks. The dedicated retry consumes its durable authorization
once, keeps attempts and records its actor/time. No real replacement ID was approved,
no Unraid/Plex/shared-provider change was made, and no release is part of this work.

The schema was generated by the existing isolated-container helper using the prior
immutable local image, with a new empty data directory, network disabled and bounded
CPU/memory/PIDs. The new migration was applied transactionally there before dumping.
No production or local application database was used to generate the snapshot.

The first candidate-image check caught a fresh-install schema round-trip mismatch:
PostgreSQL flattened the new attempt-budget constraint's nested `BETWEEN` expression
on reload. The migration now uses equivalent explicit comparisons joined by `AND`,
and the snapshot was regenerated in another owned, isolated database. Only these
two reviewed schema digests changed; their ownership classifications and retry
limits did not. The rejected candidate was not deployed.
