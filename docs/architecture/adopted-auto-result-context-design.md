# Adopted automatic result-context design

November 14, 2026 (America/New_York). Agreed scope at main

## Evidence and first boundary

The existing builder clears inherited verification status for automatic candidates,
but clears context/advisory only for prompt-confirm/select. The existing
`adoptedRagResultContext.mjs` helper likewise excludes automatic action and requires
the pending candidate's method. Its underlying live numeric witness already admits
automatic decisions; stage capture/application calls are already in place.

A local real-evaluation reproduction, with injected synthetic scoring dependencies
and no provider/database operation, gives the same result for native and
compatibility provenance:

| Observation | Current result |
| --- | --- |
| New action / method | auto_classify / policy_auto |
| New destination / library ID / score / overall confidence | B / 101 / 90 / 90 |
| Retained context destination / confidence | A / 2001 / 80 |
| Earlier advisory and nested support | Retained |
| Genuine fresh numeric proof | Available |
| Construction-context source admission | Refused by action exclusion |

Cover every newly constructed, genuinely adopted automatic candidate, including
those later completed, held for review or saved as retry. Clean attribution once
at construction. Keep initial/non-adopted/generic/legacy/manual paths and historical
rows outside this extension. Final apply/shadow/comparison/rollout still determines
which result is retained; shadow/rejection preserves the baseline.

## Small modular extension

Extend the existing context helper instead of creating another proof owner or
growing the orchestration service. Admit the three supported actions. Capture
expected method from the admitted primitive action: automatic maps to `policy_auto`,
and confirm/select map to `policy_recheck`. Require the unchanged captured action
and method when consuming the private source once. Keep that mapping independent
of current-review frame versions.

Reuse source capture immediately after successful reevaluation, before callbacks,
and application to the actual stage candidate in place. Preserve exact policy
result, typed item, loaded pool, successful stage/gate, selected library and finite
retained-confidence checks. Existing native/compatibility provenance, native
revision and active media-compatible leader validation remain authoritative.

The owned builder defaults automatic `signalContext` and `ai_advisory` to null,
as it already does for pending policy candidates. Genuine same-evaluation proof
supplies only a frozen outer `{ ranked, confidence, suggestedLibrary }`: exact
ranking and loaded-library references with fresh overall policy confidence.
Preserve the distinct leading score and maximum retained outcome confidence.
There is no new AI output, so inherited advisory stays absent.

Missing, copied/offline, changed, unbound or overflowing proof leaves the ordinary
owned defaults. Preserve the 64-candidate / 64-library / 16-KiB closed numeric proof
without truncation. That bound does not cap every attribute reachable through the
referenced ranking/library objects. Read existing own-data fields without coercion,
labels or provider text; equal public objects cannot replace private evidence.

Keep existing refusal behavior for hostile/frozen outputs. A callback that replaces
an output slot with an accessor is not repaired by this helper; it is refused
without invoking the accessor or replacing the primary operation error. Builder
defaults are not a universal sanitizer for later mutations.

## Lifetime and authority

This is construction-time ownership. The outer freeze does not freeze ranking
rows or libraries. Add no terminal-return, rollout-wait or writer-time refresh or
nulling. Later reference mutation may leave this context populated while the
independent v3 review frame correctly records a gap.

Do not borrow, consume, upgrade or reassociate review/advice/invocation receipts.
Keep v3's existing review-held admission and writer checks; completed/retry rows
still get no automatic review frame. Context proof does not establish current
database configuration or continuing permission.

Unavailable diagnostic proof must not create a new routing hold. The route gate
uses current deterministic policy identity and independent authority, not these
two cleaned fields. Preserve restrictive `ai_authority`, existing holds, budgets,
charged attempts, retries, stop/error handling and automatic's zero-extra-AI path.
Scoring, thresholds, adoption, comparison/rollout and routing/learning authorization
remain unchanged. Other inherited AI-related fields are outside this cleanup.

## Persistence and presentation effects

The whole signal context is not serialized. Removing earlier nested signals/RAG
can remove their existing persistence fallbacks. Preserve explicit top-level
signals/RAG, including current top-level fallback choices, and original automated
metadata. Earlier `relatedEvidenceSummary` no longer enters new question building.

A valid saved v1 advisory currently generates a generic historical-advisory notice.
Clearing the inherited advisory removes that notice for new ordinary automatic
candidates. New presentation, answer fingerprints and both pending Discord button
IDs can change. V3's current recommendation/score, saved safety, primary/bulk rules
and explicit destination meanings remain independent. Normal valid destination
labels still prefer actual library/current policy fields; malformed or later-mutated
fallback presentation can differ.

Existing completed-answer recovery precedes new validation. Do not rewrite History
or original decision evidence. No new user procedure or UI element is needed.

## Independent review and official research

At the user's request, GPT-6 Astra independently reviewed source and recommended
this construction-only extension. It confirmed the action/method mapping belongs
in the existing context leaf and that missing optional proof must not become a new
route refusal. A separate read-only consumer trace confirmed persistence, question,
fingerprint, Discord and selection effects. Neither review executed tests or
authorized implementation.

Official sources were discovered and opened through MCP on November 14:

- [W3C PROV-DM](https://www.w3.org/TR/prov-dm/) describes derivation from the inputs
  that actually influenced a result. The application inference is to avoid attaching
  an earlier candidate's support to a new evaluation.
- [OWASP decision/output handling](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Decisions_And_Output_Handling_Cheat_Sheet.html)
  supports contextual binding and bounded reuse. Here, diagnostic support and
  operation authorization remain separate; unavailable context is not a new denial.
- [WAI labels/instructions guidance](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions)
  supports useful, clear information without unnecessary clutter. Reuse current
  controls and remove unrelated inherited advice; no full accessibility claim follows.

## Options and final recommendation stack

| Option | Benefit | Cost or limitation |
| --- | --- | --- |
| Preserve inheritance | No change | Earlier candidate's support/advisory remains attached |
| Always null both fields | Small cleanup | Discards genuine current policy support |
| Proven minimal context or null, clear advisory | Useful current attribution with existing proof | New fallback/notice/fingerprint behavior; construction-only lifetime |
| Continuing validation | Could remove later stale context | New copy/return/writer ownership contracts and overlap with review machinery |

Recommend the third option: independent live numeric proof, captured action/method,
owned null defaults, exact construction association, minimal context or null,
independent current-review validation, existing final apply and transactional
persistence, then completed-answer recovery. Continuing context validation and the
separate pending-replacement BIGINT precision defect remain later work.
