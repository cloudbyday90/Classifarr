# Review-held automatic policy design

November 14, 2026 (America/New_York). Agreed complete batch at main

boundaries; final shared-scope agreement received. See the separate

## Eligible cohort and version

Cover new genuinely adopted automatic-policy candidates whose authoritative
derived History state is `awaiting_decision`. They must have passed existing
adoption, comparison/conflict, final apply and rollout work. Preserve the existing
reason they are held. A valid current evaluation can recommend a destination
without authorizing its automatic delivery.

Introduce automatic-only `policy.current_review.v3`, requiring action
`auto_classify` and method `policy_auto`. Preserve v1/v2 recorded and gap meaning.
Older frame-aware readers reject v3 as present unavailable evidence;
do not reinterpret formerly invalid older bytes or rewrite historical records.

Keep the existing closed frame shape, numeric ranking and detail projections.
The version denotes admission to the review-held creation cohort, rather than
requiring current row status to remain pending after an operator outcome.
Retain existing row/item/method/question-membership validation and History-row
lifetime, restore behavior, deletion and portable-backup exclusion.

## Private source and bounded lifecycle

Extend the existing adopted-review source with a captured automatic action,
version and expected method. Capture immediately after successful reevaluation,
before callbacks. Reuse the live numeric witness, immutable seed, exact typed
item/result/pool, origin/revision, active media-compatible leader, actual
stage/gate/candidate and finite retained confidence checks.

Preserve the captured attempted version before fallible inspection. Carry latent
automatic evidence through exact final apply and known owner copies without
turning it into invocation or routing authority. Unknown copies, missing/offline
proof, mutation, overflow or inspection failure become a version-bound gap when
the result enters the eligible pending cohort. They cannot revive original or
question evidence. Restoring values after observed loss cannot restore proof.

Reuse existing 64-candidate / 64-library / 16-KiB numeric proof, complete ranking
up to 64 candidates, five detail projections, six score components and 64-KiB
frame. Keep frozen numeric mechanics and proven purpose categories or explicit
unknowns. Add no raw rules, provider prose, retrieved content or diagnostic body.

Use small existing ESM source/version/contract/live leaves and a thin persistence
policy helper if needed. Do not grow the broad orchestration service or couple
this diagnostic evidence to provider permission.

## Derived-state storage boundary

Hold/check the latent receipt at existing writer entry before asynchronous state
derivation. Once the ordinary state has been derived, admit the automatic frame
only for exact `awaiting_decision`; recheck through existing lifecycle waits and
immediately before INSERT. Use that same admitted handle consistently for frame
projection and the existing row-binding INSERT selection.

Completed automatic and `pending_retry` rows emit no automatic current-review
metadata and keep the ordinary INSERT/profile/notification paths. Initial auto,
non-adopted/shadow/rejected decisions and generic/manual paths cannot manufacture
this source. Existing confirm/select admission remains unchanged.

Reuse the existing INSERT transaction and canonical actual row-ID binding. Add
no query, round trip, schema, retention job or postcommit evidence repair. Preserve
ordinary rollback, concurrency, lost/delayed acknowledgement and notification
semantics; do not replay an uncertain classification write.

## Review and action meaning

Use the shared current source for recommendation, score, evidence/cards,
comparison and decision presentation, web/bulk contracts and both saved Discord
paths. Require the retained leader to remain a permitted question candidate.
Keep original `metadata.policyResult` separately as original automated evidence.

Apply existing primary/Confirm/bulk rules to the fresh unique positive reference.
Inherited unbound adjudication is excluded by the current-source rules. A B
shortcut can therefore appear where old unbound disagreement suppressed one.
Existing ties, duplicates, gaps and native questions retain their own handling.
Do not invent mandatory selection for a healthy unique automatic candidate.

Preserve the saved route-safety projection independently. Above-threshold policy
support may display `automatic_threshold_blocked`; the actual hold and operator
authorization remain authoritative. Recorded current evidence with missing or
corrupt safety retains existing stale/retry-only protection. Add no new-version
exemption to historical-safety checks. Policy evidence gaps retain existing
generic explicit-choice behavior, with no older score/destination fallback.

Recommendations, defaults, answer fingerprints and Discord IDs can change for
new affected records. Exact completed receipts recover before current validation;
preserve explicit destination command semantics, authorization and routing/learning
permission. No displayed evidence itself selects, routes or starts work.

## Prospective verification status

As separately confirmed, clear only inherited candidate-bound verification when
constructing every new adopted automatic-policy candidate. This includes later
completed and review-held outcomes. No verification ran for that new candidate,
so future History confirmation/abstention counts must not inherit its predecessor.

Preserve historical rows, original baseline objects, genuine provider observations,
maximum outcome confidence, other context/advisory fields, top-level signals/RAG,
restrictive authority and all calls/accounting/retry/stop rules. Automatic
generation remains skipped. Current confirm/select behavior and fulfilled
verification assembly remain unchanged.

## Trade-offs and recommendation stack

Current review evidence removes the original/current mismatch while preserving
the review hold and operator actions. Costs are a new private frame version,
creation-cohort filtering, changed defaults/fingerprints and intentional future
verification-count differences. Wider automatic context/advisory cleanup and
continuing context validation remain separate.

Recommended stack: genuine live evaluation, exact action/method-bound private
receipt, bounded frame or version-bound gap, final apply, authoritative derived
pending-state admission, transactional row binding, independent saved safety,
shared current recommendation and authorized operator action with completed
receipt recovery.
