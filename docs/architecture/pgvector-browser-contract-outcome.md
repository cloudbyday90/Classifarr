## Recommendations and trade-offs

The official sources, retrieved through MCP on November 14, are linked in the
design: Playwright visible-behavior/locator/CI guidance, W3C landmark and reflow
guidance, and GitHub CI documentation. The application inference is to test the
accepted visible contract and include it in ordinary automated CI, while keeping
health/provenance semantics at their existing owners.

Restoring old prose would reverse the accepted concise interface. Updating only
local tests would retain the CI omission. Running every fixture in ordinary CI
would add a wider runtime/failure scope. The chosen approach adds five cases to an
existing bounded step, preserving product behavior with modest additional test
execution and broader ownership for that step.

Recommended stack: accepted product contract, independent expected facts, semantic
browser assertions, narrow/wide rendering checks, bounded CI selection, existing
workflow safeguards and exact-source delivery receipts. The next classification
item is construction-owned context/advisory for adopted automatic candidates. The
separately documented pending-replacement BIGINT precision defect also remains.

No open PR was available at intake or the delivery recheck, so no random PR or
stale applicable Dependabot PR could be selected. No closed PR was reused or PR
merged. This batch has no release, deployment, live configuration write, provider
call, schema, endpoint, UI change or operator CLI requirement.
