# Retained adopted result context outcome

November 14, 2026 (America/New_York). Implemented on main. See the separate
[agreed design](retained-adopted-result-context-design.md) and
[investigation/research](retained-adopted-result-context-investigation.md).

## Result

A new adopted prompt-confirm policy candidate now starts with no inherited
signal context or AI advisory. A small independent result-context service uses
the genuine live evaluation to supply only its exact ranking, fresh overall
confidence and loaded selected library. Missing, copied, offline, changed or
overflowing proof leaves explicit null. The private source is consumed once at
actual candidate establishment; optional advice, invocation permission and
saved-review detail capture do not supply this authority.

Ordinary verification skips, genuine failures and freshness refusals retain
that same candidate. Fulfilled verification continues to supply its own actual
invocation context and current advisory or absence. The original baseline,
maximum outcome confidence, restrictive authority, current policy result,
provider observations, charged invocations and ordinary error handling remain
unchanged. The existing builder still clears inherited verification status.

The numeric witness keeps its 64-candidate / 64-library / 16-KiB limits. The
minimal context's outer object is frozen, while ranking/library objects remain
the actual loaded references. The closed proof's byte limit is not a complete
size guarantee for all referenced evaluation details.

## Lifetime and observable effects

This establishes ownership at construction. It does not refresh or null context
at terminal returns, after provider/error-handler/rollout awaits or during
writer waits. Later reference mutation can leave context populated while the
independent saved review frame becomes a gap. Existing frame checks and forced
gaps retain their precedence; context cleanup never upgrades a gap or grants
AI, routing or learning permission.

In the reproduction, the retained outcome can still have confidence 80 while
its context describes fresh B with overall policy confidence 75 and leading
score 70. It no longer carries A/80 or A's advisory. This is a source/ownership
correction, not a new scoring or accuracy claim.

The full context is not serialized. Earlier nested signals/RAG are no longer
available as persistence fallbacks; explicit top-level signals/RAG keep their
existing values and precedence. Typical policy-path contexts do not always
contain those nested observations, so their removal is not claimed for every
record. Other original diagnostics and metadata remain unchanged.

Clearing the inherited advisory removes its generic legacy notice from new
retained policy results and changes presentation-inclusive fingerprints/Discord
IDs. The saved frame retains recommendation, score and evidence ownership.
Existing completed-answer recovery precedes fresh validation. Historical rows
are not rewritten.

## Next recommendation

Assess current review evidence for retained policy-only `prompt_select`
candidates. The existing frame producer/recorded validator accepts
`prompt_confirm`; select candidates remain an explicitly separate action
contract and can still lack a current frame. Start with their operator-visible
recommendation/source behavior, preserving mandatory destination selection and
all authorization. Automatic-action frames and continuing context revalidation
remain separate follow-ups.

The recommended stack remains independent live numeric proof, exact
construction binding, minimal context or null, no inherited advisory, existing
apply/frame validation, transactional persistence and completed-answer replay.
The trade-offs are changed advisory fingerprints, possible removal of nested
fallbacks and a deliberately limited construction-time guarantee.
