## Starting point and agreed scope

Started clean on main at `eb2e83af306bccd8e5aeafd55b6052feb4fc5ea8`.
Independent read-only source/surface investigations were used through the
repository grill-me/grilling workflow. The user confirmed both comparison meaning
and the complete privacy/read-only batch; no further scope agreement is pending.

The new view uses first-item-eligible purpose events and separately named frozen
policy/choice, original/choice and policy/original comparisons. It preserves
recorded action meaning and unknown original proof. Gapped/held-out item details
remain outside the listing, with complete aggregate coverage retained.

The exclusive private CLI mode reuses existing frozen inputs, query budgets,
transaction isolation and cancellation. Shared preparation preserves existing
aggregate JSON bytes and denominators. Output is limited to fifty cases / 1 MiB
after whole-cohort validation/holdouts, with exact omission counts. Only validated
numeric IDs, typed identity, times, score and fixed categories may be printed.

## Verified evidence boundary

The current supplement freezes one policy leader and its purpose evidence, not
the full policy pool or a selected policy ID. Canonical source IDs are available
without printing raw runtime event keys. Existing manual/runtime frozen decision
contexts can establish a completed original automated destination. History-review
v3 has an independently frozen served original reference, including BIGINT cases
whose older decision context is null. Missing actual manual/runtime reference IDs
remain unrecorded rather than inferred from the leader.

Full alternatives exist in a separate immutable child but are not selected by
this read. Later AI/routing fields are mutable History neighbors or insufficient
queue witnesses. They remain explicitly uncaptured in this contract. A flagged
case is not an error label, a successful route or a causal explanation.

No live aggregate, production database query or provider request was run during
this investigation. This delivery does not deploy the earlier capture feature.

## Implementation and validation

`--prospective-purpose-cases` emits one private JSON document. Separate modules
own the shared snapshot read, complete eligibility preparation, original and
command references, strict case projection, capped report and CLI read adapter.
The aggregate reducer remains independently callable and its output is embedded
unchanged in the case report. Separate comparison counts cover all eligible
events, including agreements and cases omitted by the display cap.

Only first-item eligible flagged events appear. History-review originals remain
available with null legacy context when independently frozen in v3; their method
stays unknown. Manual/runtime command-reference library IDs remain uncaptured.
No event keys, titles, actor identifiers, fingerprints or raw source objects
are projected. Full alternatives and later routing traces stay explicit gaps.

512 baseline-versus-refactor aggregate JSON/error byte comparisons passed,
including permutations, aliases, conflicts and connected holdout bridges.
Focused unit tests passed two suites / 44 tests; real PostgreSQL integration
passed two suites / 13 tests. Coverage includes 5,000-event full validation before
the fifty-case prefix, conflicts after the prefix, malformed late evidence,
exact IDs/microseconds, typed identity, independent BIGINT originals, unknown
references, privacy, option isolation, admission, cleanup and cancellation.
Real reads verified read-only repeatable-read isolation, rejection of injected
DML, coherent target availability across concurrent commits, source/checkpoint
immutability and quiet CLI output. Mutable History changes cannot rewrite the
frozen original comparison.

test: 89.20% statements/lines, 86.57% branches and 90.71% functions. The combined
coverage ratchet passed without a baseline change. Client source is unchanged;
