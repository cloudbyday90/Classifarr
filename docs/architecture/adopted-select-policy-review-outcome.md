The generic `confirm_destination` command still accepts an explicit permitted

## Recommendation stack and next item

Use genuine live select evaluation, a private action/version-bound receipt,
bounded current frame or gap, apply-only publication, transactional row binding,
one shared technical reference and explicit server-validated destination choice.
This removes stale review advice without turning the leader into operator intent.
The costs are version dispatch, new fingerprints and prospective verification
count differences; legacy/history interpretation stays stable.

Next, assess construction-owned context and advisory for new adopted select
candidates. Those fields can still belong to an earlier candidate even though
the saved technical review evidence is now current. Start with fresh minimal
policy context or explicit absence and removal of the inherited advisory, while
preserving select's no-verification behavior, outcome confidence, authority and
all apply/accounting rules. That behavior is a separate planning decision;
automatic-action frames and lifetime revalidation remain separate follow-ups.
