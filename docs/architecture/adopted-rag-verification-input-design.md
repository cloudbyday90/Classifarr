# Adopted RAG verification input design

November 13, 2026 (America/New_York). Agreed complete batch. Investigation base:
`2a626e5b0bf6d9311a52b7425955b33097ab4271` on main.
Observed result: [implementation outcome](adopted-rag-verification-input-outcome.md).

## Problem and observed behavior

The adopted verification helper spreads the earlier signal context and replaces
only its suggested library and confidence. A production-helper reproduction
therefore supplies B/75 alongside A's ranking, diagnostics, signals and nested
RAG context. The previous result-assembly change correctly returns that exact
invocation object; it does not make its inherited fields current.

Strict candidate-bound admission and response parsing accept a minimal context
containing the current ranking, overall confidence and selected loaded library.
The independently qualified optional advice/profile already projects fresh
selection evidence or omits it. Earlier rich policy diagnostics are not currently
emitted through that scoped prompt section. The defect also affects internal
context and persistence fallbacks, rather than establishing that every earlier
field reaches the provider.

## Agreed behavior boundary

For adopted prompt-confirm reruns that pass existing eligibility and mode gates,
use a separate private invocation source captured immediately after genuine
successful reevaluation, before adoption callbacks. Bind the exact expanded
typed item, policy result, loaded pool, successful stage/gate and adopted
candidate. Reuse the live numeric recovery witness, independently of optional
advice/profile and the diagnostic current-review observer.

Prepare a single-use source after existing gates. Its outer context contains only
`ranked`, `confidence` and `suggestedLibrary`. Retain current loaded references
and detect changes through the existing witness; freezing the outer object alone
does not establish continuing freshness. Preserve the existing 64-candidate,
64-library and 16-KiB numeric-witness limits. Bind the actual candidate display
prefix of at most 160 units separately from optional full-label/profile admission.

Earlier breakdown, diagnostics, summary and nested signals/RAG are absent from
this invocation. The independently supplied current RAG argument and explicit
top-level result fields keep their existing meanings. In particular, saved
signals/nested RAG fallbacks can disappear when no corresponding top-level field
exists; do not reconstruct them from the earlier pass.

## Refusal, accounting and review

Missing proof before invocation skips without charging an AI-service invocation.
Keep the already-adopted deterministic policy candidate, with an explicit
current-review evidence-gap attempt. If that candidate wins final apply selection,
the existing publication/writer path saves the gap and review requires explicit
destination selection. Returning that candidate without a frame attempt is
unsafe for this new path: a reproduced policy-gate selection of B then lets the
legacy reader recommend root pass-one A.

An entered AI-service invocation stays charged. Recheck the independent source
after existing asynchronous preparation, before every existing generation entry
and before accepting its result. A private trusted freshness refusal prevents
further dispatch and retains the deterministic candidate with the same explicit
review gap. It does not become a provider outage, resilience failure or retry.
Keep genuine rejected operations, earlier stream errors and completed provider
observations truthful. An entered transport can still complete; this provides
no cancellation, refund or replay guarantee.

The saved-frame observer remains diagnostic-only. It cannot authorize invocation
or deny a valid numeric source merely because evidence-card/profile projection
is unavailable. Keep the existing capability admission and scoped optional advice.

## Scope and verification

Use small invocation-contract/lifecycle leaves and the existing owner/service
integration points. Preserve initial verification, non-adopted verification,
generic/legacy callers, configured caps, budgets, mode selection, scoring,
comparison, rollout and routing/learning authorization. Ordinary cap/mode/
resilience skips and genuine provider-failure fallback paths stay unchanged;
their retained candidate-context cleanup is a separate follow-up.

Verify genuine evaluator and production-owner flows, all four fulfilled
verification statuses, same/different destinations, copied/retained/failed stages,
label/numeric mutations, overflow, optional-proof independence, resource cleanup
and precise invocation/generation counts. Exercise real PostgreSQL persistence,
pending HTTP, web/Discord contracts and exact completed replay, including proof
that a new refusal cannot revive A. Use loopback local/remote provider transports
for pre-dispatch waits, retries, completed responses and genuine error precedence.

Run fresh backend coverage and normal quality/security gates. Reuse client
evidence only if all inputs, installed graph and reports are unchanged; the
independent compiler assessment otherwise requires fresh client evidence. Update
the separate outcome and Unreleased, commit/push on main and inspect exact-source
CI. Add no query, schema, public result field, API/UI, setting, job, operator CLI
trigger, provider call, historical rewrite, release or deployment.

## Research and recommendation

W3C PROV-DM distinguishes an activity's inputs, outputs and derivations. OWASP's
RAG guidance separates context integrity/provenance from output enforcement.
The application-specific recommendation is one coherent invocation source with
independent authorization and explicit missing evidence; neither source mandates
this particular implementation. [W3C PROV-DM](https://www.w3.org/TR/prov-dm/),
[OWASP RAG security](https://cheatsheetseries.owasp.org/cheatsheets/RAG_Security_Cheat_Sheet.html).

| Option | Benefit | Cost or limitation |
| --- | --- | --- |
| Keep the hybrid input | Preserves all current behavior | Retains misleading earlier support and persistence fallbacks |
| Construct minimal input from public shapes | Small implementation | Does not establish genuine same-evaluation provenance |
| Private fresh input with explicit-gap refusal | Coherent input and conservative review through existing surfaces | Changes dispatch eligibility and requires precise accounting |

Recommendation stack: genuine numeric source, minimal invocation context,
existing preparation/generation checks, truthful refusal accounting, explicit
review gap, independent optional evidence, existing comparison/authorization,
then production-bound regression evidence.
