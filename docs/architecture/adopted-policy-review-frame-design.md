## Reproduced behavior

An adopted verification result identifies destination B at overall confidence
75. Its fresh policy ranking and normalized question favor B at score 75 over A
at score 20. The saved original policy ranks A at 80 over B at 30. The existing
answer contract recommends A at 80 because this adopted path supplies the
original policy source to review readers.

The reproduction uses the production result, question and answer-contract
helpers. Replacing the synthetic original policy with the fresh policy changes
the contract recommendation to B at 75. The existing prospective current-policy
review frame already solves this source selection for accepted non-adopted
verification outcomes.

The agreed first consumer extends that frame to adopted verification outcomes.
The next follow-up addresses their internal result-context and advisory
assembly, where earlier evidence can still be inherited.

## Agreed complete first batch

Create a dedicated adopted-review provenance leaf. Capture its source
immediately after successful fresh reevaluation, before gate callbacks,
candidate construction and provider work. Reuse the genuine live recovery
reference to bind the exact policy result, expanded typed item, complete numeric
ranking, overall confidence and loaded active/media-compatible library pool.
Capture the existing closed review seed at the same point.

The numeric source uses the existing label-free reader. Optional prompt advice,
display-label admission and profile availability each retain their own contracts.
A missing optional subsection can therefore coexist with a valid numeric review
source. Purpose categories use genuine frozen policy-capture evidence where
available and the established unknown categories otherwise.

Retain a private association with the actual successful adopted stage, gate and
deterministic candidate. Verify exact object associations, `hadError:false`,
`shouldAdopt:true`, `prompt_confirm`, selected-library identity and policy-result
identity. Snapshot the candidate's primitive destination, confidence and method
for later consistency checks. Its confidence can legitimately be the maximum
of baseline and fresh confidence under the current candidate builder. The saved
policy confidence always comes from the fresh evaluation.

Consume the stage association once after the existing rerun eligibility and mode
gates. Observe the actual adopted verification invocation through its completion.
This observer supplies diagnostic evidence to result publication. Existing
verification admission and provider accounting govern invocation independently.

Associate a current-frame attempt with each scoped fulfilled rerun candidate.
Cover CONFIRM, ABSTAIN, invalid output and capability refusal. When source proof
is missing, copied, changed or oversized, associate an explicit evidence-gap
attempt. Genuine rejected operations and skipped reruns retain their ordinary
candidate/error paths.

Use the existing generic final publisher after exact apply selection and the
fulfilled rollout await. Recheck the source, stage, gate, original deterministic
candidate and selected result. Existing explicit transfers carry the receipt
through owner-controlled copies. Persistence checks it at entry, after state
derivation and inside the INSERT callback. An observed proof failure is latched
and produces the existing row-bound gap representation.

Harden the shared attempt registration so failed result inspection still leaves
an evidence-gap attempt. Inspect only own data fields and validate primitive
destination/confidence/method values before constructing their comparison tuple.
This prevents hostile coercion during diagnostic inspection and keeps malformed
selected evidence within the existing gap presentation.

## Saved data and presentation

Reuse `policy.current_review.v1`, its existing projection, History INSERT and
readers. The original policy metadata continues to represent its original
evaluation. New adopted frames describe the selected fresh evaluation.

| Boundary | Existing contract used by this batch |
| --- | --- |
| Live numeric witness | At most 64 evaluated candidates and 64 pool libraries, 16 KiB |
| Saved ranking | Complete ordered numeric pool, at most 64 candidates |
| Detailed mechanics | At most five closed evidence cards, explanations and fixed support categories |
| Saved frame | At most 64 KiB with exact row ID and typed item binding |
| Lifetime | Retained with its History row, including surviving configuration restores |
| Pending review | Frame leader must belong to the permitted question candidates |
| Missing selected proof | Explicit evidence-gap frame and destination-selection presentation |

Keep overall confidence, retained candidate score and final outcome confidence
as distinct values. The saved projection uses IDs, numeric mechanics and fixed
categories. Display names continue through the existing bounded question data.

Existing shared readers supply recommendation, threshold presentation, score,
card and comparison data to pending HTTP, web/bulk answer contracts and both
Discord paths. Their completed-receipt recovery precedes fresh frame validation.
New recommendations and presentation-inclusive answer fingerprints can change.

Historical rows retain their recorded representation. History deletion removes
its frame through the ordinary row lifecycle. Portable backups continue to use
their existing sections. Current scoring, call budgets, comparison/rollout,
authorization and transaction/uncertain-outcome rules govern classification.

The implementation targets the provenance leaf, stage integration and shared
diagnostic attempt registration. Initial and non-adopted verification, legacy
callers, adjudication, policy-only adoption and existing replay form compatibility
controls. Provider transport, actual invocation context and result-advisory
assembly remain subjects of their established independent contracts.

## Research and recommendation stack

Official URLs were discovered through MCP and inspected November 13, 2026.
W3C PROV-DM describes the generation, use and derivation of data. The
application-specific recommendation is to retain the fresh evaluation's
relationship to the selected result and saved review. The existing row-bound
frame provides that relationship. [W3C PROV-DM](https://www.w3.org/TR/prov-dm/).

OWASP's RAG guidance calls for source attribution, context integrity and output
validation. The application-specific recommendation is to derive review
mechanics from bounded server-owned evidence and keep provider processing under
the existing authorization checks. [OWASP RAG security](https://cheatsheetseries.owasp.org/cheatsheets/RAG_Security_Cheat_Sheet.html).

| Recommendation | Benefit | Cost or limitation |
| --- | --- | --- |
| Extend the existing saved frame | Corrects the visible adopted-review source through established readers | Adds a bounded frame to each affected History row |
| Dedicated private adopted observer | Separates numeric review evidence from optional prompt disclosure | Adds a focused stage handoff and mutation checks |
| Explicit selected-evidence gaps | Keeps lost proof visible to review | Some new reviews require destination selection |
| Reuse existing reader and lifecycle | Uses the current review workflow and atomic row binding | Carries the existing History retention cost |

First extend adopted saved review and verify end-to-end source selection. Next
address adopted invocation-context and advisory assembly using its own concrete
behavior contract. Continue broader category-neutral evidence work from those
verified boundaries.
