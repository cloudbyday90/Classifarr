# Adopted RAG verification input outcome

November 13, 2026 (America/New_York). Implemented and locally verified. Design:
[agreed fresh-input boundary](adopted-rag-verification-input-design.md).

## Result

Eligible adopted prompt-confirm verification now receives its genuine fresh
evaluation's ranking, overall confidence and loaded selected library together.
The invocation no longer spreads earlier breakdown, diagnostics, summary,
signals or nested RAG into that context. Existing result assembly returns the
exact minimal invocation object and the current advisory or its explicit absence.

A separate small invocation owner captures a live numeric source immediately
after successful reevaluation, binds it to the actual adopted stage/gate/
candidate, and consumes the prepared handoff once. It reuses the established
64-candidate, 64-library and 16-KiB witness and binds the consumed 160-unit
display prefix. It proves consistency of the loaded evaluation, without a new
database freshness query. Optional full-label/profile advice and saved-review
diagnostics remain independent consumers.

## Refusal and observable effects

Before invocation, missing/copied/stale proof skips without a charged call.
After entry, checks run through existing asynchronous preparation and each
generation entry; acceptance rechecks after fulfillment. An entered invocation
stays charged. Private freshness refusal stops further dispatch and keeps the
already-adopted deterministic candidate with an explicit current-review gap.
Existing comparison and rollout still decide whether that candidate wins apply.

The new refusal path publishes through the existing frame/INSERT mechanism only
after final selection. A saved gap requires destination selection and cannot
revive original pass-one advice. Completed transport observations, actual stream
errors and genuinely rejected preparation operations retain their normal
observations/error handling. There is no cancellation, refund or replay promise.

Persistence no longer finds earlier signals or nested RAG in the successful
adopted invocation context. Those fields become unavailable when there is no
explicit top-level result source. Current top-level policy/RAG fields, original
automated metadata and the bounded current-review frame retain their separate
meanings. Numeric scoring, configured caps, mode/admission rules and routing/
learning authorization are unchanged.

Initial, non-adopted, generic and legacy verification remain outside this change.
Existing cap/mode/resilience skips and genuine provider-failure fallbacks still
retain their ordinary candidate/context behavior. The change does not claim to
repair every adopted fallback or reconstruct historical evidence.
