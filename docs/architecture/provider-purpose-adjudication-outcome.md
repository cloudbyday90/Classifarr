## Implemented behavior

The existing local AI adjudication request can now inspect canonical declared
positive purpose for its existing two or three candidates. The production policy
wrapper supplies a separate collector around the unchanged evaluator lifecycle.
It snapshots before asynchronous support reads, requires genuine private native
evaluation/contribution proof, and binds the exact typed item, policy/library,
positive native revision, loaded configuration, retained ranking and shortlist.
Relevant item-metadata mutation also invalidates the proof.

Three small services own structure/limits, live collection/receipt validation and
provider projection; a fourth small leaf holds the exact generation configuration.
Private WeakMaps retain the new data and empty opaque
handles; no result property, History field, stored capture/version, schema, API,
setting, job or operator trigger is added. Ordinary candidate-evidence objects,
consensus fingerprints and replay evidence remain unchanged.

Preserve identity/compatibility, role, signal, operator, original complete terms,
constraint mode, declared/effective rule weight, combination mode and loaded media
scope. Mixed policies expose only their complete canonical declared subset and
fixed omitted-origin categories. The genuine aggregate match is separate; it
does not identify individually matched terms. Existing eligibility and positive
effective intent contribution are required. Disabled, inferred-only, unknown,
unsupported, missing, copied, mutated or overflowing evidence cannot acquire
declaration authority or be repaired later within the same capture.

Limits remain 64 producer candidates, 32 declared rules and 4 KiB encoded evidence
per candidate, with existing 50-term/120-UTF-16-unit rule limits and a 16-KiB added
section. Preserve complete semantic units; never truncate a requirement to fit.
Evaluation itself is not capped or reordered by collection. A failed subsection
does not change scores or provider admission. The added-section limit is not an
overall prompt/model-context guarantee.

Only syntactically trusted local Ollama receives terms. Other providers and
untrusted Ollama hosts receive fixed availability/origin/match categories.
Both the selected host and actual generation base URL must pass that check.
The selected row and cached Ollama endpoint can differ, so the existing settings
read now supplies a private snapshot under the existing provider lock for purpose
requests. Preflight and generation consume the same snapshot. Real HTTP controls
prove a mismatched actual endpoint receives aggregates, a preflight-time settings
change cannot redirect the detailed request, and settings are read once rather
than introducing another read or provider call. A conservative IPv4-mapped
loopback endpoint exercises untrusted syntax without contacting an external host.
Escaped JSON keeps term text framed as untrusted evidence; it is not an injection
or authorization guarantee. Existing strict PROPOSE/ABSTAIN parsing, provider
quotas/retries/cancellation, routing and learning gates remain authoritative.
AI proposals may change; synthetic controls do not establish improved accuracy
or explain historical production decisions.

## Research, tradeoffs and next recommendation

The [design's official OWASP/W3C sources](provider-purpose-adjudication-design.md#official-guidance-and-application)
support separating data, provenance and enforcement. This applies those
principles without introducing a framework, extra model, UI or routine CLI.

| Choice | Benefit | Remaining cost or limit |
| --- | --- | --- |
| Live adjudication-only sidecar | Supplies actual declarations to an existing automatic local comparison | Classify/verify modes still lack this representation |
| Complete bounded units and explicit gaps | Prevents a truncated rule changing meaning | Large/legacy declarations may remain unavailable |
| Local detail, remote aggregates | Preserves the existing disclosure boundary | Remote models cannot inspect the configured terms |
| Deterministic external gates | Preserves permission and response boundaries | Prompt wording alone cannot establish injection resistance |

Next inspect category-specific assumptions in the separate classify prompt and
replace them with category-neutral guidance grounded in configured evidence.
The classify-only suffix in `classificationAiService.mjs` still names a
"Family" destination and categorically dismisses content ratings as library
indicators. Review those instructions against each library's admitted rules,
without adding a category-specific exception or changing response authority.
Do not expand this contract to an all-library or historical surface without its
own binding/disclosure assessment. Keep post-choice compatibility-purpose
learning provenance separate; this change does not widen it.

Keep runtime-security follow-up ahead of future publication: the official
[Node announcement](https://nodejs.org/en/blog/vulnerability/november-2026-security-releases)
targets security releases on or after November 11. On this November 9 delivery
check npm's registry still reports 12.2.2 as latest/next-12 and the
[12.2.3 release PR](https://github.com/npm/cli/pull/10244) remains open. A pending
release is not a qualified remediation artifact. Preserve the current pins and
known security boundaries; no new exception is introduced here.
