# Placement-informed automation and backfill design

Date: 2026-10-28. Status: recommendation following the user's modernization,
backfill and automation questions. This document does not enable a live job,
historical import or routing promotion.

## What current placements establish

Existing locations are useful observations of this installation's conventions.
`inventoryLearnedProfiles.mjs` already learns bounded relative genre, studio and
rating profiles from inventory membership. `inventoryCompanyProfiles.mjs` adds
company observations. Description/representative-profile services and existing
scheduled refresh infrastructure provide reusable building blocks.

Placement can contain earlier automated mistakes or shared/moved copies. It is
an inferred training/ranking observation, not an operator confirmation, declared
library purpose, historical event identity or proof that a previous route worked.
Do not convert the current directory into a backdated correction or change the
purpose-authority rules already implemented.

## Recommended automatic flow

1. Use existing inventory synchronization and profile refresh signals to observe
   compatible movie/TV membership and normalized descriptive metadata. Preserve
   source/version fingerprints, typed identity, synopsis grouping and bounds.
2. Derive likely destinations from existing contrastive/description evidence.
   Keep these observations in an explicitly inferred cohort. Conflicting,
   unavailable or ineligible placements cannot become favorable votes. Preserve
   declared intent and native storage authority as separate constraints.
   Compare features that distinguish peer libraries; shared comedy genres alone
   cannot establish stand-up, scripted-series or live/game-show format. Use
   supported structured cues and measure their errors before proposing promotion.
3. Passively freeze eligible complete comparisons before outcomes using the new
   identity-bound capture. This does not require a second provider decision or
   an additional review screen.
4. Capture trusted normal confirmations and destination changes automatically
   through their existing server-owned command transactions. Respect outcome-only
   consent; a particular choice does not grant generalized learning permission.
5. Run a bounded, read-only gap audit through existing scheduler/admission
   infrastructure. Publish aggregate reasons such as unbound comparison, missing
   snapshot, unknown kind, source-only identity, unavailable target and conflict.
   Use fixed reason codes and quiet status changes, not repeated per-item prompts.
6. Assess recoverable historical evidence separately. Produce a dry-run recovery
   manifest with exact source references, original clock, identity/action proof,
   proposed cohort, duplicates/conflicts and retained-window eligibility.
7. Validate suggestions on independent held-out operator choices and a disjoint
   later cohort before proposing any reversible routing promotion. Track
   regressions and abstentions by media/library; apparent sample growth alone
   cannot authorize routing.

The next bounded implementation is step five: automate the read-only audit using
existing counters and runtime controls. A following feedback-writer upgrade should
freeze its actual action and reference provenance prospectively; older flags
cannot establish that information. Neither step needs a new singleton or a
second classification model.

## Historical recovery rules

Recovery is possible only when independent retained evidence proves the original
binding. A usable archive must establish the original comparison identity,
explicit action/reference, selected destination and event time, with exact event
correlation and a source integrity receipt. A backup containing the same unbound
v1 ranking is insufficient by itself. No such qualifying archive was established
in this task, and no production backup was opened.

Missing facts cannot be supplied by current membership, current history, a
shortlist leader or a newly generated model answer. Ordinary future operator
actions supply new present-time evidence; they do not retroactively confirm old
events. Preserve missing evidence honestly when recovery cannot be proved.

Any future historical import requires its own reviewed design and dry-run
agreement. Use a separate derived historical cohort with explicit provenance,
source digest and algorithm version. Preserve original event time separately
from import time. Do not overwrite immutable receipts, recreate expired
prospective snapshots on replay, reset thirty-day evidence age or silently extend
private retention. Imports must be idempotent and transactional, with conflicts
excluded and no routing/learning writes. This is a proposed boundary, not
authorization to read secrets, modify UnRaid or retain archives indefinitely.

## Research, alternatives and final stack

Official sources were discovered/read through MCP on 2026-10-28:

- [W3C PROV-O](https://www.w3.org/TR/prov-o/) supports explicit derivation and
  attribution. Keep inferred placements, imported history and operator choices
  distinguishable rather than giving them one evidence label.
- [scikit-learn leakage guidance](https://scikit-learn.org/stable/common_pitfalls)
  supports predeclared predictions and held-out evaluation. Current placement can
  inform training without also becoming the answer used to grade that training.
- [OWASP logging guidance](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)
  supports aggregate/redacted diagnostics and careful treatment of private
  identifiers, access tokens and connection data. Audit evidence stays private.

| Option | Benefit | Cost / risk | Decision |
| --- | --- | --- | --- |
| Existing profiles plus provenance-aware automatic audit | Reuses work; explains gaps with little operator effort | Does not invent unavailable historical facts | First recommendation |
| Placement-informed inferred suggestions | Learns the installation's conventions | Can reinforce existing mistakes unless independently checked | Retain separate evidence/cohort |
| Proven archive recovery | Can recover genuinely missing history | Requires exact evidence and privacy/retention review | Dry-run before import |
| Convert all current placements to confirmed labels | Immediate apparent completeness | Circular evaluation and amplified routing mistakes | Reject |
| Ask the model to regenerate old outcomes | Easy to automate | A new guess cannot prove the original action or timing | Reject |

Recommended stack: existing inventory sync/profile workers, typed passive
captures, canonical operator receipts, an automatic read-only gap audit, separate
inferred and verified cohorts, and independently measured promotion gates.

Two useful recovery paths need distinct labels. Filling missing descriptive
features for verified current identities can improve future profiles under
existing refresh/provider budgets; it does not alter old prediction records.
A future explicitly reviewed bulk endorsement could create bounded present-time
operator observations, with exact scope and receipts. That would require a
separate command design and must not become backdated history or generalized
learning consent. Neither path was activated in this commit.
