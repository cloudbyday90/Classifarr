# Migration Guide: v0.36.x → v0.37.0

## Overview

v0.37.0 introduces the **Policy-Driven Classification Engine**, replacing the legacy rule-based system. This guide helps you migrate from v0.36.x to v0.37.0.

---

## What's Changing

### Deprecated: Legacy Rules

The `library_custom_rules` table is **deprecated** and will be removed in **v0.39.0**.

**Timeline:**

| Version | Status | Action Required |
|---------|--------|-----------------|
| v0.37.0 | Deprecated | Migration tools available, rules still work |
| v0.38.0 | Warning | UI warnings for unmigrated rules |
| v0.39.0+ | Removed | Must use policies |

### Deprecated: Event Detection

The `event_detection_type` column in `libraries` table is **deprecated** and will be removed in **v0.39.0**.

**Timeline:**

| Version | Status | Action Required |
|---------|--------|-----------------|
| v0.37.0 | Deprecated | Migration tools available, event detection still works |
| v0.38.0 | Warning | UI warnings for libraries with event detection |
| v0.39.0+ | Removed | Must use seasonal/genre presets |

**Reason for Deprecation:**

Event detection is now **fully covered by content presets**:

| Event Type | Replacement Presets |
|------------|-------------------|
| Holiday (Christmas, Halloween, etc.) | `christmas_holiday`, `halloween`, `thanksgiving`, `valentines`, `easter`, `new_years` |
| Sports | `sports_doc`, genre-based matching |
| Concert | `concert` preset |
| PPV/Combat | `sports_doc`, `action` presets |
| Awards | Custom keyword-based preset |

The policy system provides more flexibility through:
- Adjustable preset weights
- Multiple preset combinations
- Better learning from user feedback
- More granular control (e.g., Christmas vs Halloween)

### New: Policy System

Policies replace rules with a hybrid approach:

- **Presets**: 168 pre-built content definitions
- **Patterns**: Auto-discovered associations
- **RAG**: Semantic similarity
- **History**: Learning from past decisions

## Installation

### Step 1: Pull New Image

```bash
docker pull ghcr.io/cloudbyday90/classifarr:v0.37.0
```

### Step 2: Update docker-compose.yml

Ensure you're using the latest image:

```yaml
services:
  classifarr:
    image: ghcr.io/cloudbyday90/classifarr:v0.37.0
```

### Step 3: Restart Container

```bash
docker compose down

```

Check logs for successful migrations:

```bash
docker logs classifarr | grep "Migration"
```

```
✓ Migration 044: content_presets_expansion - Success
✓ Migration 045: legacy_migration_tracking - Success
```

## Post-Installation Setup

### 1. Default Policies Created

v0.37.0 automatically creates a default policy for each library:

```sql
-- Default policy created for each library
INSERT INTO library_policies (library_id, name, ...)
VALUES (123, 'Default Policy for Movies', ...);
```

Check policies:

```
Settings → Policies
```

### 2. Content Presets Seeded

168 system presets are automatically loaded:

```
Settings → Policies → Preset Picker
```

Browse by category: Genres, Ratings, Themes, Studios, etc.

## Migrating Legacy Rules

### Option 1: Migration Wizard (Recommended)

**For libraries with a few rules:**

1. Navigate to **Migration Dashboard**
2. Click library card
3. Review suggested presets for each rule
4. Select migration strategy (preset or override)
5. Migrate one-by-one or bulk migrate

**Step-by-step:**

```
1. Migration Dashboard → "Kids Movies" library card
2. Click "Migrate with Wizard"
3. Rule 1: "Genre contains Animation"
   → Suggested preset: "Animated" (95% confidence)
   → Click "Use Preset"
4. Rule 2: "Rating is G or PG"
   → Suggested preset: "Family Friendly" (100% confidence)
   → Click "Use Preset"
5. Confirm migration
```

### Option 2: Auto-Migrate

**For libraries with many rules:**

1. Navigate to **Migration Dashboard**
2. Click "Auto-Migrate All"
3. System applies top suggestion for each rule
4. Review migrated policy
5. Adjust weights/presets as needed

**When to use:**

- 10+ rules per library
- Rules map cleanly to presets (genre, rating, keyword)
- You trust the confidence scores (>80%)

### Option 3: Manual Policy Creation

**For complex or custom rules:**

1. **Create new policy**:
   ```
   Settings → Policies → Create Policy
   ```

2. **Select presets** that match your rule intent

3. **Configure thresholds**:
   - Auto-classify: 85% (default)
   - Prompt: 60% (default)

4. **Mark legacy rule as migrated** (optional):
   ```sql
   UPDATE library_custom_rules 
   SET deprecated = true, 
       migrated_to_policy_id = <new_policy_id>
   WHERE id = <rule_id>;
   ```

## Migration Examples

### Example 1: Simple Genre Rule

**Legacy Rule:**

```
Genre contains "Animation" → Kids Movies library
```

**Migration:**

1. Wizard suggests preset: **Animated** (95% confidence)
2. Click "Use Preset"
3. Policy created with preset attached

**Result:**

```json
{
  "policy_id": 1,
  "library_id": 123,
  "name": "Kids Movies Policy",
  "presets": [
    {
      "key": "animated",
      "weight": 1.0
    }
  ]
}
```

---

### Example 2: Multi-Condition Rule

**Legacy Rule:**

```
(Genre contains "Action" OR Genre contains "Adventure")
AND Rating is PG-13
→ Teen Movies library
```

**Migration:**

1. Wizard suggests:
   - Preset: **Action Adventure** (90% confidence)
   - Preset: **Teen** (100% confidence)

2. Select both presets

3. Policy created with both presets

**Result:**

```json
{
  "policy_id": 2,
  "library_id": 456,
  "name": "Teen Movies Policy",
  "combination_mode": "weighted_average",
  "presets": [
    { "key": "action_adventure", "weight": 1.0 },
    { "key": "teen", "weight": 1.0 }
  ]
}
```

---

### Example 3: Complex Custom Rule

**Legacy Rule:**

```
(Studio is "A24" OR Studio is "Neon")
AND Vote Average >= 7.0
AND NOT (Genre contains "Horror")
→ Indie Films library
```

**Migration:**

1. Wizard suggests:
   - Preset: **A24 Films** (80% confidence)
   - Preset: **Highly Rated** (100% confidence)
   - Override: Exclude Horror (manual)

2. Create policy with presets

3. Add manual override:
   ```
   Settings → Policies → [Policy] → Overrides → Add Override
   Signal Type: Genres
   Mode: Exclude
   Values: ["Horror"]
   ```

**Result:**

```json
{
  "policy_id": 3,
  "library_id": 789,
  "name": "Indie Films Policy",
  "presets": [
    { "key": "a24", "weight": 1.2 },
    { "key": "highly_rated", "weight": 0.8 }
  ],
  "overrides": [
    {
      "signal_type": "genres",
      "config": {
        "mode": "exclude",
        "values": ["Horror"]
      }
    }
  ]
}
```

### Example 4: Event Detection Migration

**Legacy Configuration:**

```sql
-- Library with event_detection_type set
UPDATE libraries
SET event_detection_type = 'holiday',
    event_sub_type = 'christmas'
WHERE name = 'Christmas Movies';
```

**Migration Options:**

#### Option A: Use Seasonal Presets (Recommended)

1. Create policy for the library
2. Attach relevant seasonal presets:
   - `christmas_holiday` (for Christmas/holiday content)
   - `halloween` (for Halloween content)
   - `thanksgiving` (for Thanksgiving content)

**Steps:**

```
1. Settings → Policies → Create Policy
2. Select library: "Christmas Movies"
3. Add presets:
   - christmas_holiday (weight: 1.5)
   - winter (weight: 0.8)
4. Set thresholds:
   - Auto-classify: 80%
   - Prompt: 50%
5. Save
```

**Result:**

```json
{
  "policy_id": 4,
  "library_id": 111,
  "name": "Christmas Movies Policy",
  "auto_classify_threshold": 80,
  "prompt_threshold": 50,
  "presets": [
    { "key": "christmas_holiday", "weight": 1.5 },
    { "key": "winter", "weight": 0.8 }
  ]
}
```

#### Option B: Custom Keyword Preset

For more specific event detection (e.g., specific sports teams):

1. Create custom preset with event-specific keywords
2. Attach to policy

**Example for NFL-specific library:**

```json
{
  "custom_preset": {
    "key": "nfl_content",
    "name": "NFL Content",
    "category": "custom",
    "signals": {
      "keywords": {
        "require_any": ["nfl", "football", "super bowl", "touchdown"],
        "weight": 2.0
      },
      "genres": {
        "prefer": ["Documentary", "Sport"],
        "weight": 1.0
      }
    }
  }
}
```

#### Migration Mapping Table

| Event Type | Event Sub-Type | Recommended Presets | Alternative |
|------------|----------------|-------------------|-------------|
| holiday | christmas | `christmas_holiday`, `winter` | Custom keywords |
| holiday | halloween | `halloween` | `horror` + keywords |
| holiday | thanksgiving | `thanksgiving` | Custom keywords |
| holiday | valentines | `valentines` | `romance` + keywords |
| holiday | easter | `easter` | `family_friendly` + keywords |
| sports | nfl/football | `sports_doc` + custom keywords | Genre: Sport |
| sports | nba/basketball | `sports_doc` + custom keywords | Genre: Sport |
| sports | mlb/baseball | `sports_doc` + custom keywords | Genre: Sport |
| sports | ufc/mma | `sports_doc` + custom keywords | Action genres |
| concert | - | `concert` | `music_doc` |
| ppv | ufc/boxing | `sports_doc` + custom keywords | Action genres |
| awards | - | Custom keyword preset | Documentary |

#### Cleanup After Migration

Once policy is working correctly, clear the event detection setting:

```sql
UPDATE libraries
SET event_detection_type = NULL,
    event_sub_type = NULL
WHERE id = <library_id>;
```

**Benefits of Policy-Based Event Detection:**

1. **More granular**: Separate Christmas from Halloween instead of generic "holiday"
2. **Adjustable confidence**: Fine-tune thresholds per library
3. **Combo detection**: Mix seasonal + genre + quality signals
4. **Learning enabled**: System learns from corrections
5. **Better accuracy**: Presets can check multiple signals (keywords + genres + release dates)

## Testing Your Migration

### 1. Enable Stats Dashboard

```
Dashboard → Policy Stats
```

Monitor:
- Auto-classification rate
- Accuracy percentage
- Corrections needed

### 2. Process Test Items

Send a few test requests via Overseerr or manual queue.

**Expected behavior:**

- Items matching presets → Auto-classified (≥85%)
- Uncertain items → Prompted (60-84%)
- Complex items → Manual review (<60%)

### 3. Review Feedback

Check classification decisions:

```
History → Recent Classifications
```

Look for:
- Correct auto-classifications
- Reasonable prompts
- No obvious misclassifications

### 4. Tune Thresholds

If too many prompts:

```
Settings → Policies → [Policy] → Thresholds
Lower auto_classify_threshold: 85 → 80
```

If too many misclassifications:

```
Raise auto_classify_threshold: 85 → 90
```

## Frequently Asked Questions

### Q: Will my existing classifications be affected?

**A:** No. Past classifications remain in history. Only new items use the policy system.

---

### Q: Can I use both legacy rules and policies?

**A:** Yes, during the deprecation period (v0.37-v0.38). Policies take precedence if both exist.

---

### Q: What if migration wizard has low confidence?

**A:** Create a manual policy or use policy overrides for custom logic that doesn't map to presets.

---

### Q: Do I need to migrate immediately?

**A:** No. You can migrate gradually. Legacy rules work until v0.39.0.

---

### Q: How do I revert a migrated rule?

**A:** Delete the policy and re-enable the legacy rule:

```sql
UPDATE library_custom_rules 
SET deprecated = false, 
    migrated_to_policy_id = NULL
WHERE id = <rule_id>;
```

---

### Q: What about my event detection settings?

**A:** Event detection (`event_detection_type`) is deprecated in favor of seasonal/genre presets. See [Example 4: Event Detection Migration](#example-4-event-detection-migration) for migration steps. Event detection will continue to work in v0.37 and v0.38 but will be removed in v0.39.

---

### Q: Can I still use event detection in v0.37?

**A:** Yes. Event detection still works in v0.37 and v0.38 but is deprecated. We recommend migrating to seasonal presets for better flexibility and learning capabilities.

---

### Q: Which presets replace my holiday event detection?

**A:** See the migration mapping table in [Example 4](#example-4-event-detection-migration). Generally:
- Christmas → `christmas_holiday` + `winter`
- Halloween → `halloween`
- Sports → `sports_doc` + custom keywords
- Concerts → `concert`

## Troubleshooting

### Migration fails with "Preset not found"

**Cause:** Preset seed data didn't load.

**Fix:**

```sql
-- Re-run preset seed migration
\i database/migrations/043_content_presets_seed.sql
\i database/migrations/044_content_presets_expansion.sql
```

---

### Policy scores are all 0%

**Cause:** Weights don't sum to 1.0.

**Fix:**

```
Settings → Policies → [Policy] → Weights
Ensure: preset + pattern + rag + history = 1.0
```

---

### Too many prompts, not enough auto-classify

**Cause:** Thresholds too conservative.

**Fix:**

```
Settings → Policies → [Policy] → Thresholds
Lower auto_classify_threshold: 85 → 75
```

---

### Presets not matching expected items

**Cause:** Signal configuration needs tuning.

**Fix:**

1. Check preset signals:
   ```
   Settings → Policies → [Policy] → Presets → [Preset] → View Details
   ```

2. Adjust preset weight:
   ```
   Increase weight: 1.0 → 1.5 (boost)
   Decrease weight: 1.0 → 0.5 (reduce)
   ```
