# Migration Guide: v0.37.0

## Overview

Version 0.37.0 introduces significant optimizations to the classification engine:

1. **AI Skip Logic** - Skip expensive AI calls when PolicyEngine is confident (≥85%)
2. **Event Detection Migration** - Convert hardcoded event detection to PolicyEngine presets

This guide helps you migrate from v0.36.x to v0.37.0.

## Breaking Changes

### Event Detection Method

**What changed:**
- `detectEventContent()` is no longer called in the classification flow
- Event types are now handled via `content_presets` with category='events'
- Libraries using `event_detection_type` are automatically migrated

**Migration required:**
- ✅ Automatic - Migration 046 handles this
- ⚠️ Custom code calling `detectEventContent()` needs updating

**Deprecated:**
```javascript
// DEPRECATED - No longer called
const eventMatch = await classificationService.detectEventContent(metadata, libraries);
```

**Recommended:**
```javascript
// Use PolicyEngine instead
const policyResult = await policyEngine.evaluateItem(metadata);
```

## New Features

### AI Optimization

Classification now skips AI for high-confidence PolicyEngine results:

| Confidence | Action | Previous Behavior | New Behavior |
|-----------|--------|-------------------|--------------|
| ≥85% | auto_classify | Call AI to verify | **Skip AI**, classify immediately |
| 60-84% | prompt_confirm | Call AI to verify | **Skip AI**, prompt user via Discord |
| <60% | prompt_select | Call AI for help | Call AI for help (no change) |

**Benefits:**
- 70-80% reduction in AI API calls
- 2-5 second latency improvement per item
- Lower costs and rate limiting concerns

### Event Presets

Six new system presets in the `events` category:

| Preset Key | Name | Matches |
|-----------|------|---------|
| `event_holiday` | Holiday & Seasonal | Christmas, Halloween, seasonal |
| `event_sports` | Sports & Athletics | NFL, NBA, Olympics, sports docs |
| `event_ppv` | PPV & Combat Sports | UFC, MMA, boxing, wrestling |
| `event_concert` | Concert & Live Music | Concerts, festivals, live music |
| `event_standup` | Stand-up Comedy | Comedy specials, stand-up |
| `event_awards` | Awards & Ceremonies | Oscars, Emmys, award shows |

## Migration Steps

### Step 1: Backup Database

```bash
# Backup your database before migrating
pg_dump classifarr > classifarr_backup_$(date +%Y%m%d).sql
```

### Step 2: Update Classifarr

```bash
# Pull latest changes
git pull origin main

# Update dependencies
cd server && npm install
cd ../client && npm install

# Restart services
docker-compose down
docker-compose up -d
```

### Step 3: Run Migrations

Migrations run automatically on startup. Verify they completed:

```bash
# Check migration status
docker-compose logs -f classifarr | grep "migration"
```

You should see:
```
[INFO] Running migration 046_event_detection_presets.sql
[INFO] Event presets created: 6
[INFO] Event detection migration complete
```

### Step 4: Verify Event Presets

Check that event presets were created:

```sql
SELECT key, name, category 
FROM content_presets 
WHERE category = 'events'
ORDER BY key;
```

Expected output:
```
      key       |          name           | category
----------------+------------------------+----------
 event_awards   | Awards & Ceremonies     | events
 event_concert  | Concert & Live Music    | events
 event_holiday  | Holiday & Seasonal      | events
 event_ppv      | PPV & Combat Sports     | events
 event_sports   | Sports & Athletics      | events
 event_standup  | Stand-up Comedy         | events
```

### Step 5: Verify Library Migration

If you had libraries with `event_detection_type` set, verify they got policies with event presets:

```sql
-- Check libraries with event_detection_type
SELECT 
    l.name,
    l.event_detection_type,
    lp.name as policy_name,
    cp.name as preset_name,
    pp.weight
FROM libraries l
LEFT JOIN library_policies lp ON lp.library_id = l.id
LEFT JOIN policy_presets pp ON pp.policy_id = lp.id
LEFT JOIN content_presets cp ON cp.id = pp.preset_id
WHERE l.event_detection_type IS NOT NULL
ORDER BY l.name;
```

Expected output:
```
    name      | event_detection_type |   policy_name    |    preset_name      | weight
--------------+---------------------+------------------+--------------------+--------
 Christmas    | holiday             | Christmas Policy | Holiday & Seasonal | 1.5
 Sports       | sports              | Sports Policy    | Sports & Athletics | 1.5
```

### Verify Performance

Check average classification time:

```sql
-- Average classification time by method
SELECT 
    method,
    AVG(EXTRACT(EPOCH FROM (completed_at - created_at))) as avg_seconds,
    COUNT(*) as count
FROM classification_history
WHERE created_at > NOW() - INTERVAL '1 day'
GROUP BY method
ORDER BY avg_seconds DESC;
```

Expected results:
```

---------------+-------------+-------
```

## Troubleshooting

### Event Detection Not Working

**Symptom:** Content that should match event presets isn't being detected

**Solution:**
1. Verify preset exists:
```sql
SELECT * FROM content_presets WHERE key = 'event_holiday';
```

2. Verify preset is attached to library policy:
```sql
SELECT lp.name, cp.name, pp.weight
FROM library_policies lp
JOIN policy_presets pp ON pp.policy_id = lp.id
JOIN content_presets cp ON cp.id = pp.preset_id
WHERE lp.library_id = YOUR_LIBRARY_ID
  AND cp.category = 'events';
```

3. Check policy is enabled:
```sql
SELECT name, enabled FROM library_policies WHERE library_id = YOUR_LIBRARY_ID;
```

4. Manually attach preset if missing:
```sql
-- Get preset ID
SELECT id FROM content_presets WHERE key = 'event_holiday';

-- Get or create policy
INSERT INTO library_policies (library_id, name, enabled)
VALUES (YOUR_LIBRARY_ID, 'Holiday Policy', true)
ON CONFLICT DO NOTHING
RETURNING id;

-- Attach preset to policy
INSERT INTO policy_presets (policy_id, preset_id, weight)
VALUES (POLICY_ID, PRESET_ID, 1.5)
ON CONFLICT DO NOTHING;
```

### AI Still Being Called

**Symptom:** Logs show AI is being called even for high-confidence items

**Solution:**
1. Check PolicyEngine is returning correct action:
```javascript
// Add debug logging
logger.info('PolicyEngine result', { 
  action: policyResult.action, 
  confidence: policyResult.confidence 
});
```

2. Verify thresholds are correct:
```sql
SELECT name, auto_classify_threshold, prompt_threshold
FROM library_policies
WHERE library_id = YOUR_LIBRARY_ID;
```

3. Default thresholds should be:
   - `auto_classify_threshold`: 85
   - `prompt_threshold`: 60

4. Adjust if needed:
```sql
UPDATE library_policies
SET 
  auto_classify_threshold = 85,
  prompt_threshold = 60
WHERE library_id = YOUR_LIBRARY_ID;
```

### Classification Confidence Too Low

**Symptom:** Event content matches but confidence is below 85%, triggering AI

**Solution:**
1. Increase preset weight:
```sql
UPDATE policy_presets
SET weight = 2.0
WHERE policy_id = POLICY_ID
  AND preset_id IN (
    SELECT id FROM content_presets WHERE category = 'events'
  );
```

2. Adjust policy weights to favor presets:
```sql
UPDATE library_policies
SET 
  preset_weight = 0.60,   -- Increase from 0.40
  pattern_weight = 0.20,  -- Decrease from 0.30
  rag_weight = 0.10,      -- Decrease from 0.20
  history_weight = 0.10
WHERE id = POLICY_ID;
```

## Rollback

If you need to rollback to v0.36.x:

### Step 1: Backup Current Database
```bash
pg_dump classifarr > classifarr_v037_backup.sql
```

### Step 2: Restore Backup
```bash
psql classifarr < classifarr_backup_YYYYMMDD.sql
```

### Step 3: Checkout Previous Version
```bash
git checkout v0.36.3
docker-compose down
docker-compose up -d --build
```

**Note:** Event detection will revert to `detectEventContent()` method
