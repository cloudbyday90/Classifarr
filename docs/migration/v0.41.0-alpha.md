# Migration Guide: v0.40.x → v0.41.0-alpha

## Overview

v0.41.0-alpha delivers major improvements to system monitoring, documentation, user experience, and automation workflows. This release also **retires the legacy event detection system**, completing the migration path started in v0.37.0.

**Release Date:** February 1, 2026

---

## Breaking Changes & Migrations

### 1. Event Detection System Retired (Epic #168)

The event detection system has been **completely removed** in this release. This completes the deprecation cycle started in v0.37.0.

**What Was Removed:**

- **Database**: `event_detection_type` and `event_sub_type` columns from `libraries` table (migration 072)
- **Backend**: `detectEventContent()` function and all event detection logic
- **Frontend**: All event/holiday UI controls in library settings
- **Presets**: All 6 event presets removed from system:
  - `event_holiday` (Christmas, Halloween, Thanksgiving, etc.)
  - `event_sports` (NFL, NBA, MLB, etc.)
  - `event_ppv` (UFC, boxing, wrestling)
  - `event_concert` (concerts, live performances)
  - `event_standup` (comedy specials)
  - `event_awards` (Oscars, Grammys, etc.)

**Migration Required:**

If you were using event detection, you must migrate to PolicyEngine presets:

| Old Event Type | Replacement Presets |
|----------------|-------------------|
| Holiday (Christmas) | `christmas_holiday`, `winter` |
| Holiday (Halloween) | `halloween` |
| Holiday (Thanksgiving) | `thanksgiving` |
| Holiday (Valentine's Day) | `valentines` |
| Holiday (Easter) | `easter` |
| Sports (any) | `sports_doc` + custom keywords |
| Concert | `concert` |
| PPV/Combat | `sports_doc`, `action` presets |
| Awards Shows | Custom keyword-based preset |

**Migration Steps:**

1. Navigate to **Settings → Policies**
2. For each library that used event detection:
   - Click **Configure** on the library policy
   - Add appropriate seasonal/genre presets from the table above
   - Adjust weights if needed (recommended: 1.5 for primary preset)
3. Test with sample content to verify classifications

**Benefits of Policy-Based Approach:**

- ✅ More granular control (separate Christmas from Halloween)
- ✅ Adjustable confidence thresholds per library
- ✅ Combine seasonal + genre + quality signals
- ✅ System learns from your corrections
- ✅ Better accuracy with multi-signal matching

### 2. Sync Error Handling Changes (Fix #226)

**Change:** Missing libraries now return HTTP 404 instead of HTTP 500

**Affected Endpoints:**
- `POST /api/libraries/:id/sync`
- `POST /api/media-sync/sync/:libraryId`
- `GET /api/media-sync/items/:libraryId`

**Old Behavior (v0.40.x):**
```json
HTTP 500 Internal Server Error
{
  "error": "Something went wrong"
}
```

**New Behavior (v0.41.0-alpha):**
```json
HTTP 404 Not Found
{
  "error": "Library not found"
}
```

**Action Required:**

If you have external integrations calling these endpoints, update your error handling to expect 404 responses for missing libraries instead of 500 errors.

**Example Update:**

```javascript
// Old code
try {
  await fetch(`/api/libraries/${id}/sync`, { method: 'POST' });
} catch (error) {
  // Any error treated as server failure
  console.error('Server error:', error);
}

// New code
const response = await fetch(`/api/libraries/${id}/sync`, { method: 'POST' });
if (response.status === 404) {
  // Handle missing library specifically
  console.warn('Library not found:', id);
} else if (!response.ok) {
  // Handle other errors
  console.error('Server error:', response.status);
}
```

## Upgrade Steps

### 1. Backup Your Database

**Critical:** Always backup before upgrading.

```bash
docker-compose exec postgres pg_dump -U classifarr classifarr > backup_$(date +%Y%m%d).sql
```

Or if using embedded PostgreSQL:

```bash
docker exec classifarr pg_dump -U postgres classifarr > backup_$(date +%Y%m%d).sql
```

---

### 2. Pull Latest Image

```bash
docker-compose pull
```

Or update your `docker-compose.yml`:

```yaml
services:
  classifarr:
    image: ghcr.io/cloudbyday90/classifarr:v0.41.0-alpha
    # ... rest of config
```

---

### 3. Run Migrations

Migrations run automatically on startup:

```bash
docker-compose up -d
```

**Monitor Migration Progress:**

```bash
docker-compose logs -f classifarr | grep -i migration
```

**Expected Output:**

```
✓ Migration 072: Remove event detection columns - Success
✓ Migration 073: Discord learning tables - Success
✓ Migration 074: Expanded confidence settings - Success
```

---

### 4. Verify Health

Navigate to **Dashboard → System Health** and verify:

- ✅ All services show "healthy" or "connected"
- ✅ No degraded services
- ✅ Trend indicators display correctly

### 5. Review New Features

Explore the new functionality:

1. **Settings → Confidence Settings**
   - Review all thresholds

## Troubleshooting

### Migration 072 Fails: "Event presets still in use"

**Cause:** Policies still reference deprecated event presets.

**Fix:**

1. Navigate to **Settings → Policies**
2. For each policy with event presets:
   - Click **Configure**
   - Remove event preset (event_holiday, event_sports, etc.)
   - Add replacement preset from migration table above
   - Save policy
3. Restart container to retry migration

---

### Migration 072 Fails: "Cannot drop column with data"

**Cause:** Libraries still have `event_detection_type` set.

**Fix:**

Run this SQL to clear event detection settings:

```sql
UPDATE libraries
SET event_detection_type = NULL,
    event_sub_type = NULL
WHERE event_detection_type IS NOT NULL;
```

Then restart container.

---

### Getting 404 Errors After Upgrade

**Expected Behavior:** This is correct for missing libraries.

**Action Required:** Update API integrations to handle 404 responses properly (see [Sync Error Handling Changes](#2-sync-error-handling-changes-fix-226)).

---

### Service Lockdown Preventing Actions

**Cause:** Required services not configured or unhealthy.

**Fix:**

1. Navigate to **Dashboard → System Health**
2. Check which services are degraded/unhealthy
3. Click service name to go to settings
4. Configure the service properly
5. Verify service shows "healthy"

---

### Auto-Learning Not Working

**Cause:** Rate limits may be exceeded, or learning disabled.

**Fix:**

1. Navigate to **Settings → System → Auto-Learning**
2. Verify learning is enabled
3. Check rate limit status
4. Increase limits if needed:
   - User daily limit: 50 (default)
   - Library hourly limit: 20 (default)

---

### Confidence Settings Not Saving

**Cause:** Invalid threshold values.

**Fix:**

Ensure thresholds follow this logic:
- Auto-classify threshold ≥ Verification threshold
- Verification threshold > 0
- All thresholds ≤ 100

Example valid configuration:
- Auto-classify: 85%
- Verification: 60%

---

### Custom Rules Referencing event_detection_type

**Cause:** Custom rules still check for event detection.

**Fix:**

Update custom rules to use preset-based matching instead:

**Old Rule:**
```sql
WHERE event_detection_type = 'holiday'
```

**New Rule:**
```sql
WHERE policy_id IN (
  SELECT policy_id 
  FROM policy_presets 
  WHERE preset_key IN ('christmas_holiday', 'halloween', 'thanksgiving')
)
```

## Rollback Plan

If critical issues occur, rollback to v0.40.x:

### Step 1: Restore Database

```bash
docker exec -i classifarr psql -U postgres classifarr < backup_20260201.sql
```

### Step 2: Downgrade Image

Update `docker-compose.yml`:

```yaml
services:
  classifarr:
    image: ghcr.io/cloudbyday90/classifarr:v0.40.5d-alpha
```

### Step 3: Restart

```bash
docker-compose down
docker-compose up -d
```

**Note:** Features added in v0.41.0 will not be available after rollback.
